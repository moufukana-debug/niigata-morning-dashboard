# 朝の業務スタート画面

新潟県少年自然の家で朝の確認に使う、スマホ優先のローカルWebアプリです。勤務予定表PDFと調整プログラムExcel、または貼り付けた調整プログラムのテキストをブラウザ上で読み込み、選択した日付の「西村」さんの勤務・団体行事・注意点・最初にやることを1カラムで表示します。

## 作るものの要約

- ローカルで動く単体HTML/CSS/JavaScriptアプリ
- PDF: `260429_R8.05月_勤務予定表.pdf` をファイル選択で読み込み
- Excel: `.xlsx` / `.xls` / `.xlsm`（例: `R8_5月調整プログラム（前半）.xlsm`）をファイル選択で読み込み
- テキスト: Excelからコピーした範囲や、日付・団体名・時間・活動・場所が分かる調整プログラム文面を貼り付けて読み込み
- 今日の日付に該当する情報だけを優先表示
- メモ欄とチェック項目は `localStorage` に自動保存
- ベージュ、アイボリー、くすみブラウン系のカードUI

## 実装方針

1. まず資料をブラウザ内で読み込みます。サーバーへアップロードしません。
2. PDFはテキストを行単位に並べ、`西村` 行と当日日付列を優先して簡易抽出します。
3. PDFの表構造が崩れる場合は、抽出元を「PDF簡易抽出（要確認）」として表示し、断定しません。
4. Excelは全シートを読み、当日日付に近い行から団体名・時間・活動・場所・備考を推定します。
5. Excelが手元にない場合は、調整プログラム欄へ貼り付けたテキストを表形式の行として解析します。
6. 不足や判定不能な値は必ず `要確認` と表示します。
7. 朝に見る順番として、上から「勤務」「注意点」「最初にやること」「団体・行事」「基本情報」「メモ」にしています。

## 使用技術と理由

- HTML/CSS/JavaScript: 初心者でもファイル構成が分かりやすく、GitHub Pagesへ置きやすいため。
- PDF.js: ブラウザだけでPDFテキストを読み取るため。
- SheetJS: ブラウザだけで `.xlsx` / `.xls` / `.xlsm` のセルデータを読み取るため。マクロは実行しません。
- localStorage: ローカル環境でメモとチェック状態を保存するため。

## 実装コード

主な実装場所は以下です。

- `index.html`: ファイル選択、調整プログラムのテキスト貼り付け、勤務、注意点、タスク、団体・行事、メモ欄のHTML
- `styles.css`: 韓国カフェ風の配色、カードUI、スマホ1カラムレイアウト
- `src/app.js`: PDF/Excel/貼り付けテキスト解析、今日の日付抽出、`要確認` 表示、localStorage保存

## 起動方法

### ローカルサーバーで開く方法（おすすめ）

PDF.jsなどのライブラリを安定して読み込むため、ローカルサーバーで開く方法をおすすめします。

```bash
python3 -m http.server 8000
```

その後、ブラウザで次を開きます。

```text
http://localhost:8000
```


### GitHub Pages project siteで開く場合

このリポジトリは project site として、次のURLで動く前提です。CSSとJavaScriptは `./styles.css` と `./src/app.js` の相対パスで読み込みます。

```text
https://moufukana-debug.github.io/niigata-morning-dashboard/
```


## 「タイトルだけ表示」になった場合の確認

GitHub Pages の project site では、`/styles.css` や `/src/app.js` のような先頭スラッシュ付きパスにすると、`https://moufukana-debug.github.io/styles.css` のようにリポジトリ名なしの場所を見に行って失敗します。このアプリでは `./styles.css` と `./src/app.js` の相対パスを使います。

また、`app.js` 自体が読み込めない場合は `app.js` の中に書いたエラー表示処理も実行されません。そのため、`index.html` 側に最小限の起動監視を置き、JavaScriptファイルの読み込み失敗・実行時エラー・初期化未完了を画面にも表示します。

## 使い方

1. 「勤務予定表PDF」で `260429_R8.05月_勤務予定表.pdf` を選びます。
2. 「調整プログラムExcel」で `.xlsx` / `.xls` / `.xlsm` の調整プログラムを選びます。例: `R8_5月調整プログラム（前半）.xlsm`。
3. Excelファイルが使えない場合は、「調整プログラム（テキスト貼り付け）」にExcelからコピーした範囲や調整プログラム文面を貼り付け、「テキストを反映」を押します。テキストを反映した場合は、Excelファイルより貼り付け内容を優先して団体・行事を解析します。
4. 必要に応じて「確認する日付」を変更します。
5. まず「今日の勤務」と「注意点」を確認します。
6. 「最初にやること」を3つだけチェックします。
7. 気づいたことは「ひとことメモ」に書きます。


## 抽出精度改善の方針

今回の改善では見た目よりも抽出精度を優先し、次の順番で情報を扱います。

1. 勤務予定表PDFの `西村` 行と今日の日付列の交差セルを、PDFテキストの座標情報から優先抽出します。
2. 座標で取れない場合だけ、行テキストを使った簡易抽出に戻します。
3. 特記事項・備考・注意・連絡などの行から、今日の日付列または今日の日付を含む内容を拾います。
4. 調整プログラムExcelは、日付が見つかった行の下方向ブロックと、日付が列見出しになっている表の両方を確認します。
5. 団体名・時間・活動・場所・備考のどれかが不足した場合は、補完せず `要確認` と表示します。

画面は「勤務」「注意点」「団体」「要確認」を分け、スマホは1カラム、Windowsなど広い画面では最大幅を抑えた2カラムで表示します。


## 調整プログラムExcel解析の改善

調整プログラムは結合セルや複雑な配置がある前提で解析します。SheetJSの merge 情報を使って結合セルの代表値を周囲の空セルにも反映し、補完後の2次元グリッドから「日付らしいセル」「団体名らしいセル」「時間らしいセル」「活動名らしいセル」「場所らしいセル」「担当らしいセル」を探します。そのうえで、1団体を複数行のブロックとしてまとめ、今日の日付ブロックに近い団体イベント候補を組み立てます。

表示は次の3段階です。

- 完全一致: 今日の日付候補と、団体・時間・活動・場所が揃っているもの。
- 候補あり・要確認: 今日の日付周辺または列見出しから見つかったが、不足項目があるもの。
- 要確認: 日付一致は弱いが、団体候補など資料上の手がかりがあるもの。

画面には解析ログとして、読み込んだシート名、結合セル補完の有無、日付候補数、団体ブロック候補数、採用件数を表示します。

日付セルは、SheetJSが持つ表示文字列も利用して読み取ります。これにより、Excel内部では数値として保存されているが画面上は日付表示になっているセルも、`2026/5/13`、`2026-05-13`、`5/13`、`05/13`、`5月13日`、`R8.05.13`、`令和8年5月13日` などの表記として照合できます。

### 団体名候補の誤抽出対策

団体名候補は、学校名・園名・協会・団・少年団・研修会・教室・クラブ・会などの団体/行事キーワードを含むものを優先します。西村などの所員名、担当欄や職員欄の値、日本人名らしい2〜4文字の短い名前、時間・場所・活動セルは団体名から除外します。各団体カードには、採用した団体名候補、除外した候補、採用理由、シート名と行番号付近をデバッグ表示します。

### 公開反映確認

画面上部に `Version: debug-2026-05-13-text-1` と `Branch: work` を表示しています。GitHub Pages に反映されたか確認するときは、まずこの表示が変わっているかを確認してください。Excelを選択した直後には、解析前でも「ファイル選択イベントは動作しました」と表示され、ArrayBuffer取得、XLSX.read、シート検出、解析結果件数まで段階的に更新されます。

### Excel読込デバッグ

Excelを選んだ後、またはテキストを反映した後、団体抽出の前に「本当にブック・セル相当の行が読めているか」を画面で確認できます。表示する内容は、ファイル名または入力種別、拡張子、サイズまたは文字数、ファイル読込成否、Workbook生成成否、シート名、シートごとの行数・列数、結合セル件数、先頭シートまたはテキスト入力の最初の20行プレビューです。これにより、`読み込めない` 状態と `読み込めたが団体抽出できない` 状態を分けて確認できます。
